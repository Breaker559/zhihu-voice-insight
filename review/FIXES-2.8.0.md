2.8.0 修复说明

这次处理整页空白与高频明细展示。旧版 `locate` 会从页头个人链接一路向上找到包含正文的 body，`itemContainer` 又允许向上四层兜底，最终把页面祖先当作回答折叠或隐藏。已用原版代码和本地 DOM 重现 body 被隐藏、页头与控制入口一起消失的情况。

现在从最近的明确回答／文章容器定位，验证只有一块独立正文，排除页面根节点、主栏、导航、侧栏和包含多条内容的外框。插入、屏蔽和恢复共用已验证卡片状态，屏蔽前再次验证作者和节点身份；识别失败时跳过。

新增“本页高频与屏蔽名单”：列出当前已读取的高频作者及被折叠／隐藏作者，支持逐人显示、本页全部恢复、永久白名单。命中记录展示起止时间、实际跨度、精确到秒的时间、相邻间隔、标题、类型、字数和摘录。证据从完整采样保留，不受最近 N 条设置截断；相同记录组会合并。暂时放行对本页后续扫描生效，永久放行写入白名单。

同时修复直接影响这些功能的问题：摘要不用于短文屏蔽；HTML 兜底按作者过滤；接口失败不缓存成空成功；统计缓存包含配置签名；扫描使用 generation 防止关闭后回填；观察器忽略自身 DOM 写入，按钮只在内容变化时更新；多 worker 完成后才释放扫描状态；默认动作改为文档约定的仅标记，保留已有用户配置。

验证：17 项 Chromium 回归测试通过，包含原版故障反例与当前版修复验证；JavaScript 语法和 diff 空白检查通过。测试使用构造页面与模拟接口，尚未验证真实知乎的登录态、最新 DOM 或 Tampermonkey 宿主差异。布局预览：`2.8.0-evidence.png`。

上一次 `REVIEW.md` 和 `results.json` 是 2.7.0 的历史检查结果；`reproduce.py` 现固定读取那个原始 Git 提交。当前修复验证使用 `tests/test_userscript.py`。本轮没有修改可选 AI 评分与 AI 结果缓存逻辑，历史报告中的这两项仍待单独处理。
